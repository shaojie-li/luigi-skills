# Web UI 实现

先查项目的组件目录、主题变量、安装的 UI 库和相邻页面示例。不要根据这个 Skill 推断项目已安装 Base UI、shadcn 或私有组件；缺失的依赖必须按实际任务评估。

使用 lt 发现资产时，以当前配置来源的 `lt list` 或实际 registry 索引为准；不要凭旧示例或 Skill 名称推断同名 UI 组件可安装。源码仓库的 catalog 表示当前维护内容，分发索引可能仍保留历史版本。来源已撤回的组件不再作为新依赖推荐；消费项目中已有的组件先检查实际实现，不因远程撤回而自动删除。表单、表格的实现指导与具体 UI 资产独立。

新项目默认采用本基建的 React 命名约定：组件符号与单文件组件用 PascalCase，例如 `TaskDialog.tsx`；需要按职责拆分时使用 `taskDialog/index.tsx`，目录仅将组件名首字母改为小写，内部子组件保持 PascalCase。小组件不强制建立目录，工具与 Hook 文件用 kebab-case；`main.tsx` 只承载应用启动。已有项目优先遵循其明确规则，不批量重命名无关文件。项目若有 `docs/coding-standards.md`，先读取其中的具体约束。

维护源码分发型组件库时，将资产分组与组件内部拆分区分开：独立资产可以有自己的目录，但不为复制安装目标路径而重复嵌套源码目录；按仓库清单声明路径映射。Storybook 示例直接引用实际组件源码，留在分发目录之外，避免把示例数据与预览依赖安装进消费项目。

输入草稿、搜索和交互状态放在最近的使用组件；按独立职责和状态生命周期拆分，避免高频状态放在页面根部驱动无关大列表。不要按固定行数拆分，或机械添加 `memo`、`useMemo`、`useCallback`；性能问题用 Profiler 和具体交互验证。Hooks 检查通过不代表没有额外渲染，也不代表已启用 React Compiler。

如果项目使用 Base UI 或 shadcn Base UI，沿用项目中实际安装版本的组合 API，不套用其他原语库的属性约定。优先复用已有按钮、输入框、弹层和布局，不在业务页面重复实现焦点管理、键盘导航和弹层定位。

使用已有语义 token 表达颜色、间距和交互状态。品牌差异优先通过主题表达；确需独立视觉时保留项目约定的可访问性和暗色表现。

实现前明确页面的正常、加载、空、错误和禁用状态，仅覆盖实际存在的分支。表单错误需要关联到对应输入，异步操作需要处理失败和重复提交；图标按钮需要可访问名称。

完成后运行项目已有的必要检查，并实际验证本次改动涉及的键盘操作、焦点和窄屏布局。没有浏览器或无法启动页面时，明确哪些行为只经过静态检查。不要为单次页面需求扩充通用组件框架。
